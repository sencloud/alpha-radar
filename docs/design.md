# 设计说明

## 为什么这样分层

```text
        +---------------------------------------------+
        |  agent 层（Codex harness + deepseek-flash）  |  <- 发现/判断/移植/记录
        |  AGENTS.md  ·  .codex/skills/alpha-radar     |
        +---------------+-----------------------------+
                        | 只能通过下面的 CLI / Python API 操作
        +---------------v-----------------------------+
        |  编排层  pipeline.py  ·  cli.py              |
        +---+-----------+-----------+-----------------+
            |           |           |
   +--------v--+ +------v-----+ +---v----------+
   | harvest   | | strategies | | data         |
   | TradingView| | 信号库     | | Tushare+缓存 |
   +-----------+ +------+-----+ +---+----------+
                        |           |
                 +------v-----------v------+
                 |  engine.py（撮合/成本）  |  <- 只有一处交易规则
                 |  indicators / metrics   |
                 +-------------------------+
```

**分层的唯一目的：把「可能被 agent 改坏的东西」和「必须稳定的东西」隔开。**

- `engine.py` 是契约：成本、滑点、撮合顺序、T+1、日内强平只在这里实现一次。
  策略不能自己算钱，否则每个策略的成本口径都会不一样。
- `strategies/` 只输出信号。这样 agent 移植新策略时只需要产出四个列，
  不可能因为写错撮合而「造出」一条好看的曲线。
- `data/` 负责一切外部访问与缓存，agent 不允许绕过它直接调 Tushare
  （限流、覆盖区间、增量补拉都在这一层处理）。

## 为什么要做 agent 层

策略研究是**长尾、重复、且大量是否定结论**的工作。人做这件事的瓶颈不是聪明，
而是耐心：读 300 个 Pine 脚本、跑 50 组参数、把失败原因写下来。
这恰好是 agent 擅长的形态。

但 agent 有两个已知失效模式，必须用工程手段约束：

1. **过度拟合地报喜**：跑 300 组配置挑最好的那个，然后当成「发现」。
   → `AGENTS.md` 强制要求声明搜索规模、给分年表、报样本量。
2. **悄悄改口径**：为了好看而调整成本假设或撮合顺序。
   → 交易规则集中在 `engine.py`，策略只能产出信号。

## 数据层设计

- **增量缓存**：每个合约一个 CSV + 一个 `.cover.json` 记录已覆盖区间。
  重复回测零请求；缺头补头、缺尾补尾；空缺口（节假日）也记入覆盖，
  避免反复探测。
- **分块拉取**：Tushare 分钟线单次上限 8000 行，按周期换算分块天数
  （1min→20 天、5min→45 天…）。
- **主力连续**：按 `fut_mapping` 切段，逐段取数。
  换月跳空不会污染均线与 ATR；段末夜盘归下一段。
- **夜盘归属**：夜盘（>=20:00）归下一个交易日，与国内行情软件口径一致。
  这样「一个交易日」在数据里是连续的，日内强平可以简单地取当日最后一根 K。

## 引擎设计

事件循环按 bar 推进，逐根处理 `出场 → 更新跟踪止损 → 入场 → 日终盯市`。

撮合顺序（偏保守）：

1. 开盘已越过止损 → 按开盘价 ± 滑点全平
2. 开盘已越过止盈档 → 按开盘价成交（限价单，价格更优）
3. 盘中触及止损 → 按止损价 ∓ 滑点全平（**止损优先于止盈**）
4. 盘中触及止盈档 → 按档位价成交，分批减仓
5. 时间止损 / 收盘强平

A 股 T+1 在 `_manage` 的最前面短路返回：当日买入当日不产生任何卖出，
包括止损。这不是保守假设，是交易所规则。

## 已知取舍

- **不含冲击成本与涨跌停无法成交**：小资金假设。资金量变大后需要补。
- **按收盘价成交**：分钟级回测的通用近似，实盘会有偏差。
- **体制闸门按当根判定**：会有边界抖动，已用「连续两根确认」缓解。
- **主力连续拼接**：跨段处不做复权，指标按段独立计算以规避跳空。
